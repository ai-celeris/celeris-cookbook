# Contributing to the Celeris Cookbook

## What makes a good example

- **Self-contained**: one directory under `examples/`, runnable with only
  `CELERIS_BASE_URL` and `CELERIS_API_KEY` set.
- **Small**: a focused notebook or mini-app that explains what it demonstrates
  and shows the expected output.
- **OpenAI SDK first**: Celeris is OpenAI-compatible; use the official OpenAI
  SDK pointed at the Celeris base URL rather than hand-rolled HTTP.
- **Budget-aware**: respect the 8192-token total window. Explicit
  `max_tokens` values must be positive multiples of 256, and prompt tokens plus
  `max_tokens` must fit the window. The service defaults an omitted value to
  2048. Reuse the validation and budgeting helpers from the getting-started
  notebook.
- **Offline-friendly checks**: CI never calls the real API. Anything that runs
  in CI (typechecks, compiles, registry validation) must work without
  credentials.
- **No secrets**: never commit API keys, traces, or `.env` files.
- **E2E-classified**: every Markdown fence declares `docs-e2e=live` with an
  `expect=...` oracle, or `docs-e2e=skip`. A stateful notebook declares one
  `metadata.docs_e2e` object so the scheduled production test executes all of
  its code cells in order.

## Adding an example

1. Create `examples/<kebab-case-name>/` containing either:
   - a **Jupyter notebook** (`<name>.ipynb`), markdown cells become the page
     prose; commit outputs only if they contain nothing sensitive; or
   - a **mini-app**, code plus a `README.md` (title as the first `# heading`,
     then what it does, how to run it, sample output). The README becomes the
     website page.
2. Register it in `registry.yaml`:

   ```yaml
   - title: Human-readable title
     path: examples/<name>/<name>.ipynb   # or examples/<name>/README.md
     slug: <name>
     topic: getting-started
     description: One-sentence description shown on the index page.
     date: YYYY-MM-DD
     authors:
       - celeris
     tags:
       - getting-started
   ```

3. Optionally add an entry to `authors.yaml` to customize display name,
   website, and avatar.
4. Classify every fenced block. Use `live` only for a standalone API example;
   setup commands, illustrative output, fragments, and deployment commands are
   `skip`. Notebook code cells share state, so classify the notebook once:

   ```json docs-e2e=skip
   "docs_e2e": {"classification": "live", "expect": "nonempty"}
   ```

5. Run the checks locally:

   ```sh
   python3 -m pip install -r requirements-snippets.txt
   python3 scripts/validate.py
   python3 scripts/check_snippets.py

   cd tests/typescript-snippets
   npm ci
   npm test
   ```

6. Open a pull request. CI runs the same validation plus unit tests and
   typecheck/build jobs for the standalone examples.

The published page on docs.celeris.ai/cookbook is generated by the docs
site's build from your README/notebook, no site code lives in this repo.

## Registry rules

- `path` must exist in the repository and be a `.md` or `.ipynb` file under
  `examples/`.
- `slug` must be unique and URL-safe (`a-z0-9-`).
- `topic` controls the sidebar group. Use one of `getting-started`,
  `interactive-apps`, `agents`, `production`, or
  `evals-and-optimization`.
- `tags` are free-form but reuse existing tags where possible; the site's
  filter list is derived from them.
